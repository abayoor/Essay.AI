# Slipstream — инструкции для разработки

Slipstream — платформа велосипедного сообщества. Проект делает один школьник; объясняй изменения коротко и доброжелательно.

## Стек

- Vite + React 18 + TypeScript;
- wouter для маршрутов;
- Supabase для авторизации и всех данных;
- Vercel публикует сайт после `git push`.

Не заменяй этот стек без отдельного согласования.

## Обязательные правила

1. Новые данные добавляй только через миграции в `supabase/migrations/`.
2. Для каждой таблицы с пользовательскими данными включай RLS и политики по `auth.uid()`.
3. Не используй `service_role`, не показывай и не коммить `.env` или ключи.
4. Запросы к Supabase храни в `src/lib/`, страницы — в `src/pages/`, переиспользуемый UI — в `src/components/`.
5. Используй TypeScript без `any`; не оставляй `console.log` и неиспользуемый код.
6. Перед коммитом выполняй `npm run build`.

## Работа с базой

```bash
npm run db:new -- имя_изменения
npm run db:push -- --dry-run
npm run db:push -- --yes
```

Не проси пользователя вставлять SQL вручную в Supabase Dashboard. Если CLI попросит пароль базы, пользователь вводит его только в терминал, а не в чат.

## Keep-alive

Таблица `entries` сохранена специально для ежедневного keep-alive. После изменения базы или workflow запускай:

```bash
npm run keep-awake:setup
```

Не удаляй `.github/workflows/keep-awake.yml` и не помещай ключи в workflow. Команда сама безопасно читает локальное окружение, проверяет ping и GitHub Actions run.

## Карта развития

Первая фаза: профиль райдера, гараж, обслуживание, журнал поездок и маршруты.

Следующие фазы: групповые заезды, челленджи, сегменты, опасности, события и маркетплейс. Для них таблицы уже существуют; новый интерфейс добавляй отдельными задачами, не ломая готовую первую фазу.
